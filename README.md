
Эфир (Ether) — Приватный E2EE Мессенджер

Эфир — это веб-мессенджер с сквозным шифрованием (E2EE), построенный на базе Firebase. Он позволяет создавать приватные комнаты, обмениваться сообщениями, которые могут прочитать только участники комнаты, так как ключи шифрования хранятся локально у пользователей и никогда не передаются на сервер.

✨ Возможности

· 🔒 Сквозное шифрование (E2EE): Все сообщения шифруются на стороне клиента алгоритмом AES-256-GCM. Ключи комнат генерируются локально и хранятся в localStorage. Без ключа расшифровать сообщения в Firebase невозможно.
· 💬 Реальные комнаты: Создавайте приватные комнаты с уникальным идентификатором.
· 📎 Присоединение по ключу: Чтобы вступить в чат, достаточно скопировать и вставить ключ комнаты (ROOM_ID:KEY_BASE64), который отображается в шапке чата.
· 📱 Адаптивный дизайн: Интерфейс корректно отображается на десктопах, планшетах и мобильных устройствах (с поддержкой свайпов для открытия меню).
· 🟢 Статус «онлайн»: Отслеживание, кто сейчас в сети (глобально и в конкретной комнате).
· ✅ Статус доставки: Двойная галочка (✔️) появляется у сообщения, когда получатель (или любой другой участник) заходит в комнату.
· 🗑️ Управление сообщениями:
  · Удаление своих сообщений для всех.
  · Ответы на сообщения (Quoting): Возможность ответить на конкретное сообщение (реализовано с помощью всплывающей панели и визуальных цитат).
· 🧹 Автоматическая очистка базы данных:
  · На уровне комнаты: Если в комнате накапливается более 50 МБ данных, самые старые сообщения автоматически удаляются.
  · Глобально: Если общая база данных превышает 900 МБ, запускается глобальная очистка старых сообщений из всех комнат.
· 👤 Идентификация: Каждому пользователю присваивается уникальный цвет на основе его ID, что облегчает визуальное отслеживание авторов сообщений в групповых чатах.


🛠 Технологический стек

· Frontend: HTML5, CSS3 (Flexbox/Grid, CSS Variables), Vanilla JavaScript (ES6+).
· Шифрование: Web Crypto API (AES-GCM).
· База данных и бэкенд: Firebase Realtime Database (используется для хранения сообщений, статусов, присутствия).
· Иконки: Font Awesome 6.

🚀 Как развернуть проект на своей Firebase

Чтобы запустить «Эфир» на собственной инфраструктуре Firebase (своя база данных), выполните следующие шаги:

1. Создайте проект Firebase

1. Перейдите на Firebase Console.
2. Нажмите «Создать проект».
3. Назовите проект (например, my-ether-messenger) и отключите Google Analytics (или оставьте по желанию).

2. Настройте Realtime Database

1. В боковом меню выберите «Realtime Database».
2. Нажмите «Создать базу данных».
3. Выберите местоположение сервера (ближайшее к вашей аудитории).
4. Важно: В режиме безопасности выберите «Запуск в тестовом режиме» (пока не настроите правила). Позже вы их измените на более безопасные.

3. Получите конфигурацию Firebase

1. В настройках проекта (иконка шестеренки рядом с "Project Overview") перейдите в раздел «Общие».
2. Прокрутите вниз до пункта «Ваши приложения».
3. Нажмите на иконку </> (веб-приложение), чтобы добавить приложение.
4. Зарегистрируйте приложение (можно назвать его app).
5. Скопируйте объект конфигурации firebaseConfig. Он выглядит примерно так:
   ```javascript
   const firebaseConfig = {
       apiKey: "AIzaSy...",
       authDomain: "your-project.firebaseapp.com",
       databaseURL: "https://your-project-default-rtdb.firebaseio.com",
       projectId: "your-project",
       storageBucket: "your-project.appspot.com",
       messagingSenderId: "123456789",
       appId: "1:123456789:web:..."
   };
   ```

4. Обновите код

1. Откройте файл index.html.
2. Найдите строки, где объявлен firebaseConfig (примерно 200-я строка в блоке <script>).
3. Замените существующие значения на ваши скопированные данные.
4. Сохраните файл.

5. Разместите файл на хостинге

Вы можете загрузить файл на любой статический хостинг:

· GitHub Pages: Создайте репозиторий и загрузите index.html.
· Firebase Hosting: Выполните команды firebase init hosting и firebase deploy (если установлен Firebase CLI).
· Любой другой: Просто загрузите файл на любой веб-сервер или хостинг статических сайтов.

📜 Правила безопасности Firebase

ВНИМАНИЕ: Ниже приведены рекомендуемые правила безопасности. Они не требуют авторизации, но защищают структуру данных от хаотичного изменения.

1. В консоли Firebase перейдите в Realtime Database -> вкладка «Правила».
2. Вставьте следующий код и нажмите «Опубликовать»:

```json
{
  "rules": {
    // Глобальное присутствие пользователей (кто онлайн)
    "presence": {
      "$user_id": {
        ".read": true,
        ".write": "auth == null && $user_id === newData.child('online').val() ? true : false",
        ".validate": "newData.hasChildren(['online', 'lastSeen'])"
      }
    },
    // Корневой узел комнат
    "rooms": {
      "$room_id": {
        // Читать может любой, кто знает ID комнаты (т.к. нет авторизации)
        ".read": true,
        // Писать может любой, но с проверкой структуры
        ".write": true,
        
        // Присутствие внутри комнаты
        "presence": {
          "$user_id": {
            ".write": true,
            ".validate": "newData.hasChildren(['online', 'lastSeen', 'roomId'])"
          }
        },
        
        // Сообщения
        "messages": {
          "$message_id": {
            ".validate": "newData.hasChildren(['data', 'from', 'ts']) && newData.child('data').isString() && newData.child('ts').isNumber()",
            // Разрешаем удалять только отправителю или всем (но для удаления не требуется auth, потому что нет логина, поэтому правило "write" открыто, но структура контролируется)
            ".write": true
          }
        }
      }
    }
  }
}
```

Объяснение правил:

· Отсутствие auth: Поскольку в мессенджере нет регистрации, правила не требуют аутентификации (auth == null). Безопасность обеспечивается сложностью угадывания $room_id.
· Присутствие: Пользователи могут записывать свой статус в presence и rooms/.../presence.
· Сообщения: У сообщений строго проверяется наличие полей data (шифрованный текст), from (ID пользователя) и ts (время). Это предотвращает запись "мусора" в базу.
· $user_id: В правилах присутствия проверяется, что пользователь пишет только под своим ID (переменная $user_id), что предотвращает подмену чужого статуса.

📁 Структура данных Firebase

Проект использует следующую структуру:

```
- presence (глобальный онлайн)
   - [userId]: { online: true, lastSeen: timestamp, currentRoom: roomId }

- rooms
   - [roomId]
       - presence (онлайн в комнате)
           - [userId]: { online: true, lastSeen: timestamp, roomId: roomId }
       - messages
           - [messageId]
               - data: "base64_encrypted_message"
               - from: "userId"
               - ts: 1699123456789
               - delivered: true (опционально)
               - replyTo: { id: "...", text: "...", from: "..." } (опционально)
```

🧩 Реализованные функции (подробнее)

1. E2EE: Ключ генерируется через window.crypto.subtle. Шифрование и дешифрование происходит на стороне клиента.
2. Ответы: При нажатии на кнопку "Reply" (иконка ответа) всплывает панель. Отправляемое сообщение получает поле replyTo с ID и текстом исходного сообщения. При отображении цитата вставляется внутрь блока сообщения.
3. Ленивая загрузка (Пагинация): История загружается порциями по 30 сообщений. При скролле вверх появляется кнопка "Загрузить предыдущие сообщения".
4. Управление размером БД: Функции roomCleanupBySize и globalCleanupBySize рекурсивно подсчитывают размер (в байтах) сообщений и удаляют самые старые, если превышен лимит. Это предотвращает разрастание базы и экономит бюджет Firebase.

⚠️ Важные замечания

· Отсутствие авторизации: Любой, кто получит ссылку на ваш хостинг и узнает ID комнаты (или угадает его), сможет читать сообщения, если у него будет ключ. Ключи передаются только через "пригласительную ссылку" (текст вида ROOM_ID:KEY). Никогда не публикуйте ключи комнат в открытых источниках.
· Безопасность правил: Рекомендуемые правила выше дают полный доступ на запись (write: true) для простоты работы. Если вы планируете использовать приложение в узком кругу, можно оставить как есть. Если вы опасаетесь спама, можно усложнить правила, но это потребует внесения изменений в код (добавление токена или простой аутентификации).
